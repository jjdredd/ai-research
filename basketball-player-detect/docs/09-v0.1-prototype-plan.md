# v0.1 Prototype Plan: Full v1 Functionality, Zero Training, Relaxed Bars

Status: **proposal**. Position: sits **between v0 (`04`) and v1 (`08`)** in the
build order. v0.1 delivers the **entire v1 feature set** — quarter-length
sessions, multi-class detection, team assignment, persistent individual
identification via jersey number + team + appearance — but under two
deliberate concessions:

1. **No model training or fine-tuning whatsoever.** Every learned component is
   a stock, publicly downloadable pretrained checkpoint. No detector
   fine-tune, no JNR fine-tune, no synthetic-data rendering, no custom
   training of any kind. (Ground-truth *labeling for evaluation only* stays —
   labels never train anything.)
2. **Accuracy gates at v0 level or slightly above, explicitly below v1.**
   The relaxed bars exist precisely *because* we refuse to fine-tune: stock
   weights on basketball footage will underperform, and we say so up front
   instead of moving goalposts later.

Plus: **no speed requirements** (see § Speed: none, by design). Testing
procedure once built: `10-testing-guide.md` § 3 (v0.1 table, incl. the
machine-checked no-training invariant).

## Why this variant exists

- **Feature-risk before training-investment.** Identity fusion, gallery
  merging, team voting, shot-cut handling, `players.json` schema — this is
  the integration risk of v1. v0.1 exercises all of it with zero training
  latency, so v1's fine-tunes slot into a pipeline already proven to run.
- **The stock baseline row.** v0.1's benchmark numbers become the *frozen
  lower bound* on `bench/mini-2026-10/`: every v1 fine-tune must beat its own
  v0.1 row before we believe the fine-tune narrative.
- **License-clean by construction.** Every default here is already the
  commercial-safe choice from `06` (RF-DETR Apache weights, MIT trackers,
  SigLIP Apache embeddings, PaddleOCR Apache). There is no "avoid in product"
  row to trade away later.

## Feature parity with v1 (and the one honest exception)

| v1 capability | v0.1 status | How, without training |
|---|---|---|
| Quarter-length session, no manual restart | ✅ same | identical architecture |
| Shot-boundary scan + per-shot tracker reset, gallery persists across cuts | ✅ same | PySceneDetect — classical, no ML |
| Multi-class detection `player` / `referee` / `ball` | ✅ functionally | COCO-pretrained detector gives `person` + `sports ball` off the shelf; `referee` is a **heuristic class** (see stage [3']) |
| Tracker A/B + basketball priors (count, speed gate, inbounds ROI) | ✅ same | OC-SORT/BoT-SORT need no weights; priors are hand-written rules, not learned |
| Team assignment (Home/Away) | ✅ same | HSV histogram k-means — already training-free in v1 |
| Persistent identity gallery + tracklet merge | ✅ same | pretrained embedding backbones only (A/B below) |
| Jersey-number reading + majority vote | ✅ functionally | **stock PaddleOCR CRNN, no fine-tune** — expect materially worse digits than v1's tuned reader |
| Team+number fusion with confidence + failure reasons | ✅ same | fusion is business logic; the "never silently guess" rule is a *correctness* requirement, not an accuracy one — it stays at full v1 strength |
| TrackEval mini-benchmark + regression gate | ✅ same | shared benchmark; labels are eval-only |
| Court homography | ❌ still out | out in v1 too (v2+) |

## Architecture (stages = `08` with stock-weight substitutions)

```
video (quarter-length) ──► [0] shot-boundary scan (PySceneDetect)
              │
              ▼
      [1] Stock COCO-pretrained detector     RF-DETR (Apache wts; default)
              │                              classes: person, sports ball
              │                              low conf (0.3); NO fine-tune, ever
              ▼
      [2] Tracker A/B                        OC-SORT (static) vs BoT-SORT (motion)
              │                              + hand-coded basketball priors
              ▼
      [3] Team assignment                    HSV histograms → k-means k=2 + manual override
              │
      [3'] Referee heuristic                 dark-kit vs team palettes + inbounds ROI
              │                              + on-court dwell time → referee class flag
              ▼                                 (measured, never gated)
      [4] Tracklet-merge + gallery           SigLIP embeddings (Apache wts) A/B'd
              │                              vs OSNet/CLIP-ReID pedestrian ckpts
              ▼                              → game-long player clusters
      [5] Jersey number (stock OCR)          PaddleOCR pretrained CRNN on gated crops;
              │                              majority vote per cluster, accrues over quarter
              ▼
      outputs: players.json (Home #7 | Home #? | unknown-3 + failure reason)
               + overlay video + metrics.json
```

No fine-tune directories, no `annotate/` training-set tooling, no synthetic
number renderer (that exists only to train — dropped).

## Components & decision criteria (all pretrained)

| Stage | Choice (stock weights) | License | Rejected option & why |
|---|---|---|---|
| 1 Detector | RF-DETR pretrained (COCO person + sports ball) | ✅ Apache code+weights | YOLO11m stock — fine for research, AGPL weights; keep as fallback for detector-quality A/B only (`06`) |
| 1b Ball | COCO `sports ball` from same detector | ✅ (same) | TrackNet-class models excluded: no official weights (`06`), would need training |
| 2 Tracker | BoT-SORT / OC-SORT via `roboflow/trackers` (MIT reimplementations) | ✅ MIT + Apache | BoT-SORT's bundled ReID ckpts ⚠️ research-terms — run tracker with appearance off, or appearance replaced by stage-4 embeddings |
| 3 Team | HSV k-means (identical to `08`) | n/a | learned team-affiliation net — would need training; dark-kit games fall back to manual override |
| 3' Referee | heuristic: color distance from both team palettes + inbounds dwell + size prior | n/a | trained `referee` class — fine-tune territory, v1 only |
| 4 Embeddings | SigLIP (default) vs OSNet/CLIP-ReID pedestrian ckpts — A/B, both stock | Apache / MIT code, ⚠️ research-data weights (flag, don't retrain) | any domain-adapted ReID — none are open (`06`); fine-tuning is out of scope here |
| 5 JNR | PaddleOCR **stock, general model, no fine-tune** | ✅ Apache code+weights | Koshkina pipeline — no weights published, ❌ reference-only (`06`); CRNN fine-tune — v1 only |

| (opt) Crop gating | pretrained pose model (MMPose zoo, Apache) for front-facing heuristic, or pure heuristics (aspect, detector-conf) | ✅ | pose model is optional; skipping it must not change acceptance |

## Benchmark & measurement

- **Shared benchmark:** the same `bench/mini-2026-10/` defined in `08` § Data
  & benchmark plan (10–15 min SportsMOT-format labels incl. team + jersey
  number). Labels are consumed for scoring only — **no stage reads them at
  training time**, and no component's weights are updated in this variant.
- v0.1 runs produce the **stock-baseline row** in the benchmark table; v1
  numbers are reported *against* them.
- If v1's labeling budget shrinks after v0 findings, v0.1 shrinks with it —
  they must remain the same frozen set.

## Acceptance criteria (v0.1 bar: ≈v0, slightly above; below v1)

| Dimension | v0 bar (recall) | **v0.1 bar** | v1 bar (for contrast) |
|---|---|---|---|
| Session | 2–5 min clips | quarter-length end-to-end, no restart (functional, not accuracy) | same as v0.1 |
| Detection | "≥90% visible players", eyeballed | **no beat-stock requirement** (stock *is* the component); recall ≥70% on normal slice, ≥45% on occluded slice (<50% visible area) — measured on benchmark, deltas recorded | fine-tuned beats stock on all 3 slices |
| Tracking | ≥6/10 players hold ID >5 s | **IDpurity ≥0.6**; IDsw/min recorded, within ±20% of v0 ByteTrack baseline on the same clip (basketball priors buy robustness, not gate-crushing accuracy) | IDpurity ≥0.9, IDsw/min materially < v0 |
| Team | out of scope | **accuracy ≥85%** on labeled frames | ≥95% |
| Jersey number | out of scope | **top-1 ≥45%** on readable crops (stock OCR ceiling); readable-crop fraction recorded, not gated | top-1 ≥85%, ≥60% readable |
| Named players | out of scope | **≥3 of 10 starters** correct team+number by quarter end; **failure-reason requirement unchanged — never a silent wrong name** | ≥8/10 starters |
| Ball | out of scope | tracked when detected; presence recorded, **no gate** | (v1 gates nothing on ball either) |
| Referees | v0: expected as failures | flagged as class; precision recorded, **no gate** | explicit trained class |
| Runtime | ≥10 FPS or <3× realtime | **explicitly none — see next section** | ≥5× realtime, recorded |

The *shape* of the bars: every number is one deliberate notch below v1, and
none of them require beating something that a fine-tune would beat.

## Speed: none, by design

v0.1 has **no runtime acceptance criterion**. It may run below 1 FPS and
still pass. This freedom is spent on:

- Running the OCR pass on **every gated crop of every frame** (v1 samples at
  2 FPS per its open question #2) so number-accuracy measurement is not
  confounded by sampling.
- Running the **full SigLIP vs OSNet/CLIP-ReID embedding A/B** on all
  clusters, all frames.
- Allowing a second, slower tracker configuration sweep per clip.

**Possible optimizations, explicitly optional** (apply *after* acceptance,
each must re-verify metrics move <2% — none are in the critical path):

| Optimization | Notes |
|---|---|
| JNR crop-gating (height >96 px, front-facing by pose/aspect heuristic, detector-conf floor) | v1's gate, adopted late purely to cut OCR volume |
| OCR/ReID frame sampling (every N-th frame; numbers accrue over a quarter anyway) | v1's default strategy; measure its accuracy cost here |
| Batch inference for detector/OCR/embeddings; FP16 | standard, no metric change expected |
| Smaller pretrained variants (RF-DETR-S vs -B; lightweight SigLIP) | must re-run benchmark — this is exactly the trade v0.1 is free to defer |
| Track-every-other-frame + interpolation when motion is slow | last resort; changes tracker semantics |

## Risks & mitigations (v0.1-specific deltas on top of `08`)

| Risk | Mitigation |
|---|---|
| Stock COCO detector confuses spectators/refs with players heavily | inbounds ROI polygon + team-palette proximity + track-dwell heuristics; *gates are already lowered to absorb this* |
| Stock OCR reads jersey digits terribly (font, curvature, occlusion) | quarter-long majority-vote accumulation per cluster (votes accrue; a few clean crops suffice); accept `#?`; ≥3/10 named bar is set for this reality |
| Pedestrian embeddings mis-cluster identical kits | same fusion rule as v1 (team color + trajectory + priors, never embeddings alone); SigLIP-vs-OSNet A/B here produces the evidence for v1's embedder choice |
| Heuristic referee class mislabels dark-kit players in dark-vs-dark games | manual team-color override (already in v1 plan) marks both palettes "dark" → referee heuristic disabled, refs unclassified, recorded |
| Slow runs tempt silent scope cuts mid-build | speed is *not* a metric anywhere; cut nothing, run overnight |

## Time box

~1 week part-time: M1 ≈ 2 days (labeling parallel, shared with v1 budget),
M2 ≈ 2 days, M3 ≈ 1.5 days, M4 ≈ 1.5 days. No training loops; the schedule is
integration + measurement. If M2 fails, debug before M3 — a pipeline that
can't hold an ID for a quarter can't be evaluated on identity accuracy.
